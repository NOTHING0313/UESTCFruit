## 3. 测试真实性说明

- PASS 是否包含断言：是。每个自动 PASS 用例均记录 InvariantChecks。
- 是否包含状态不变量：是。覆盖 Stack、RemainingFrames、target/source 查询、Remove 后可见性、生命周期增长趋势。
- 是否包含操作计数：是。ExpectedOperations / ActualOperations / OperationCountMeaning 均写入用例结果。
- 是否包含 GC 统计窗口：是。Setup 与 Measured 分开记录。
- 是否包含 seed：Fuzz 用例记录固定 seed 和 Last 50 operations。
- 是否包含未覆盖边界：是。ManualRequired 与 NotCovered 单独列出。
- Query Performance：TryGetBuff 记录 ExpectedHitQueries / ActualHitQueries / ExpectedMissQueries / ActualMissQueries；GetBuffs(target) 记录 ExpectedNonEmptyQueries / ActualNonEmptyQueries / ExpectedEmptyQueries / ActualEmptyQueries / ReturnedViewChecks。
- Fuzz action 名称映射：Add、Remove、Tick、Refresh、TryGet、GetBuffs、AddTwiceAndTick、ClearAll。
- Fuzz model 更新规则：Add / Remove / Tick / Refresh / Query 后以 public TryGet 可见性同步 expectedActive；expectedStack <= 0 一律视为 inactive；duration 不精确模拟时只做 public query 合法性弱不变量。
- Fuzz 失败分类：包含 PotentialRuntimeBehaviorMismatch 字样时仅表示 public behavior 需要人工复核，不代表本入口已证明 runtime bug。

## 12. 风险与结论

- 默认使用 Quick Profile；Heavy Profile 通过 AllowHeavyProfile 常量保护，避免误卡 Unity Editor。
- 性能用例只记录指标，不因耗时本身判 FAIL；操作未完成、异常或不变量失败才判 FAIL。
- 测试只使用 in-memory World、BuffDefinitionRegistry 和 BuffEffectRegistry，不创建正式 Buff asset。
- 当前结论：Quick Profile PASS / Standard 未运行 / Heavy 未运行
- Standard Profile 未默认运行，需人工菜单或后续专门入口触发。
- Heavy Profile 仍由 AllowHeavyProfile=false 保护，默认不运行。
- CompressedParallel 自动覆盖状态以覆盖矩阵为准；不能自动测的项目标记为 ManualRequired。
- 本测试不证明 rollback-ready。
- 本测试不证明 View 场景表现正确。
- 本测试不证明 production whitelist 安全。
- 本测试不等价于完整 PlayMode / 网络同步测试。
