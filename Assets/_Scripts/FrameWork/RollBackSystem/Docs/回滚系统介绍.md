## 二、RollbackBootstrap — 场景入口与自动挂载

**文件**: `RollbackBootstrap.cs`

### 启动时序

```
Start()
  → yield return null（等一帧，确保 TimeSimulator 已 Awake）
  → InitCoro()
      → TimeSimulator.Instance 获取 World / SimulateRunner
      → FindObjectOfType<UnityInputAdapter>() 发现输入适配器
      → Mount()
```

### Mount() 内部逻辑

```
① 创建 PlayerSnapshotInputApplier（输入写入器）
② 创建 SimulationFrameCommandBuffer + CommandApplier + FrameCommandSourceAdapter
   （帧命令正常执行 / 回滚重放适配器）
③ 创建 WorldRollbackAdapter（ECS → IRollbackableWorld 桥接）
④ 创建 SnapshotRingBuffer<EcsWorldSnapshot>(_snapshotRingCapacity)
⑤ new RollbackCoordinator(InputBuffer, AuthoritativeInputBuffer, SnapshotBuffer, Adapter, Comparer, ChecksumBuffer, AuthoritativeChecksumBuffer)
   └─ Coordinator.CurrentFrame 从 0 开始
   └─ TickLength 从 Runner 同步
⑥ coordinator.SaveSnapshot() — World 处于 Idle，保存初始快照
⑦ AutoDiscoverPlayers() — 遍历 World.AliveEntities，找 PlayerTagComponent，注册到 InputApplier
⑧ DetachSimulationInitializerInput()
   └─ 反射置空 UnityInputAdapter._world / _playerEntity
   └─ adapter.WriteInputToWorld() 变为无操作，输入写入改由回滚管线接管
⑨ Hook Runner.BeforeTick += OnBeforeTick
⑩ Hook Runner.AfterTick  += OnAfterTick
⑪ _mounted = true
```

### 公开 API

| 方法/属性 | 说明 |
|-----------|------|
| `Coordinator` | 获取 RollbackCoordinator 实例 |
| `InputApplier` | 获取 PlayerSnapshotInputApplier（注册/移除玩家） |
| `World` | 获取当前 ECS World |
| `ConfirmFrame(int frame)` | 标记某帧已被服务端确认，释放该帧前所有缓存数据 |
| `ReceiveRemoteInput(int frame, input)` | 接收远程权威输入，触发回滚校验与重模拟 |
| `SetExpectedFrame(int frame)` | 设置服务端期望帧号，Update 中自动检测并加速追帧 |
| `ExpectedFrame` | 获取当前服务端期望帧号 |

### 关键设计

**DetachSimulationInitializerInput 的零侵入机制**：
- `UnityInputAdapter` 通过 `_world` 和 `_playerEntity` 字段直接写 ECS
- Bootstrap 不要求对方改代码，而是通过 `FieldInfo.SetValue(null)` 将其置空
- adapter 的采样逻辑正常执行（`CollectSnapshot` 仍可用），但内部 `WriteInputToWorld` 因字段为 null 而跳过
- 输入写入由 `OnBeforeTick → coordinator.Step → world.Simulate → InputApplier.Apply` 完整接管

**加速追帧 Update 循环**：
- 每 Unity 帧检查 `_expectedFrame - CurrentFrame` 是否 > 1
- 落后时通过 `TickMultiple()` 在一个 Unity 帧内执行多次逻辑 Tick
- 受 `MaxTicksPerUnityFrame` 限制（默认 3），防止逻辑帧堆积

## 三、RollbackCoordinator — 核心调度器

**文件**: `Rollback/Core/RollbackCoordinator.cs`

**泛型签名**: `RollbackCoordinator<TInput, TSnapshot> where TSnapshot : ISnapshot`

**核心属性**:

| 属性 | 类型 | 说明 |
|------|------|------|
| `CurrentFrame` | `int` | 当前逻辑帧号 |
| `TickLength` | `float` | 每逻辑帧时长（默认 1/60s） |
| `MaxTicksPerUnityFrame` | `int` | 每 Unity 帧最多执行逻辑 Tick 数（默认 3） |
| `ConfirmedFrame` | `int` | 服务端已确认的最高帧号 |

### 3.1 Step — 正常推进一帧

```csharp
public void Step(TInput input)
{
    int nextFrame = CurrentFrame + 1;
    _inputBuffer.Save(nextFrame, input);         // ① 缓存预测输入（供后续回滚重放）
    _world.Simulate(input, ctx);                 // ② 写输入到ECS + 执行BeforeTick命令
    CurrentFrame = nextFrame;                    // ③ 推进帧号
}
// 注意：Step 不调用 World.Tick，Tick 由外部 Runner 驱动
```

### 3.2 TickMultiple — 批量推进多帧

```csharp
public void TickMultiple(int count, Func<int, TInput> inputProvider)
{
    int actualCount = Math.Min(count, MaxTicksPerUnityFrame);
    for (int i = 0; i < actualCount; i++)
    {
        int nextFrame = CurrentFrame + 1;
        TInput input = inputProvider(nextFrame);
        Step(input);
    }
}
```

用于加速追帧场景，在一个调用中连续推进多帧。受 `MaxTicksPerUnityFrame` 上限保护。

### 3.3 SaveSnapshot — 保存快照

```csharp
public void SaveSnapshot()
{
    var snapshot = (TSnapshot)_world.Capture(CurrentFrame);  // 完整ECS World快照
    if (snapshot == null) return;
    _snapshotBuffer.Save(snapshot);                          // 存入环形缓存
    SaveChecksum();                                          // 同时保存Checksum
}
```

调用时机：AfterTick 中，World 处于 Idle 状态，每 `_snapshotIntervalFrames` 帧一次。

### 3.4 ReceiveAuthoritativeInput — 收到权威输入

```csharp
public void ReceiveAuthoritativeInput(int frame, TInput input)
{
    // ① 输入时序校验：过时帧丢弃
    if (frame <= _confirmedFrame) { /* log + return */ }

    // ② 重复帧检测：同帧内容相同直接忽略
    if (_authoritativeInputBuffer.TryGet(frame, out var existing))
        if (_inputComparer.IsEqual(existing, input)) return;

    // ③ 保存权威输入
    _authoritativeInputBuffer.Save(frame, input);

    // ④ 与本地预测输入比对
    if (!_inputBuffer.TryGet(frame, out var predicted)) return;
    if (_inputComparer.IsEqual(predicted, input)) return; // 预测命中

    // ⑤ 触发回滚
    int preRollbackFrame = CurrentFrame;
    if (!RollbackTo(frame - 1)) return;            // 回滚失败（快照过期）

    _inputBuffer.Save(frame, input);               // 权威输入覆盖预测输入
    ResimulateTo(preRollbackFrame);                // 逐帧重模拟追上
}
```

**输入比较逻辑**（`PlayerInputSnapshotComparer`）：
- 逐字段比较：`moveX`、`moveY`、`mouseX`、`mouseY`、`mouseWorldX`、`mouseWorldY`
- 所有按钮 flags 逐位比较（`buttonFlags`、`buttonPressedFlags`、`buttonReleasedFlags`）
- 浮点字段使用 `Mathf.Approximately`（内部精度 ~1e-6）

### 3.5 RollbackTo — 回滚到历史帧

```csharp
public bool RollbackTo(int frame)
{
    bool found = _snapshotBuffer.TryGetNearestSnapshot(frame, out var snapshot);
    if (!found) return false;        // 快照已过期
    _world.Restore(snapshot);        // 完整恢复 ECS World
    CurrentFrame = snapshot.Frame;   // 帧号回到快照帧
    return true;
}
```

**TryGetNearestSnapshot 查找逻辑**：二分查找 O(log n)，返回 ≤ frame 且帧号最大的快照。

**World.Restore 恢复内容**：
- 所有 Entity（ID / Version / Alive 状态精确还原）
- 所有 Component 值数据（Position / Velocity / Buff / Health 等）
- ComponentStore dense 数组 / ArcheType 分配表 / Singleton 注册表

### 3.6 ResimulateTo — 重模拟追上

```csharp
private void ResimulateInternal(int targetFrame, Action<TSnapshot> onEachFrame)
{
    while (CurrentFrame < targetFrame)
    {
        int nextFrame = CurrentFrame + 1;
        if (!_inputBuffer.TryGet(nextFrame, out var input))
        {
            // 输入缺失：使用 default 保持帧号连续，确保状态一致性
            input = default;
        }
        var ctx = new SimulationContext(nextFrame, TickLength, true);  // isRollback=true
        _world.Simulate(input, ctx);    // 写输入 + BeforeTick帧命令
        _world.Tick(ctx);               // 执行World.Tick + AfterTick帧命令
        var snapshot = (TSnapshot)_world.Capture(nextFrame);
        if (snapshot != null) _snapshotBuffer.Save(snapshot);
        SaveChecksum();
        CurrentFrame = nextFrame;
        onEachFrame?.Invoke(snapshot);
    }
}
```

**重模拟与正常推进的关键区别**：
- `SimulationContext.isRollback = true` → 帧命令系统进入**重放模式**
- `Simulate` + `Tick` 在同一次调用内连续执行（正常推进时两者跨 Runner 事件分隔）
- 每帧结束后立即 `Capture` 保存新快照（避免后续回滚可用快照链不完整）
- 输入缺失时使用 `default(TInput)` 继续推进，保持帧号连续

### 3.7 ConfirmFrame — 确认帧释放

```csharp
public void ConfirmFrame(int frame)
{
    if (frame <= _confirmedFrame) return;  // 防止退化
    _confirmedFrame = frame;
    // 清理所有缓冲区中 frame 之前的数据
    _inputBuffer.ClearBefore(frame);
    _authoritativeInputBuffer.ClearBefore(frame);
    _checksumBuffer.ClearBefore(frame);
    _authoritativeChecksumBuffer.ClearBefore(frame);
    _snapshotBuffer.ClearBefore(frame);
}
```

收到服务端确认消息时调用，释放已确认帧前的所有缓存数据，确保内存不无限增长。

## 四、WorldRollbackAdapter — ECS 桥接

**文件**: `Rollback/Core/WorldRollbackAdapter.cs`

**实现接口**: `IRollbackableWorld<TInput> : ISnapshotable<ISnapshot>, ISimulationChecksum`

### Simulate — 写输入阶段

```
Simulate(input, ctx)
  ├─ FrameCommandSource.ApplyCommandsAtTiming(world, frame, BeforeTick, isRollback)
  │   └─ 正常推进: 执行该帧注册的BeforeTick命令
  │   └─ 回滚重放: 重放历史BeforeTick命令（不消费）
  └─ InputApplier.Apply(world, input)
      └─ 将 PlayerInputSnapshot 写入对应玩家Entity的 PlayerInputSnapshotComponent
```

### Tick — 逻辑执行阶段

```
Tick(ctx)
  ├─ World.Tick(ctx) — 执行所有 System（InputMove / Movement / BuffSystemBridge ...）
  └─ FrameCommandSource.ApplyCommandsAtTiming(world, frame, AfterTick, isRollback)
      └─ 正常推进: 执行该帧注册的AfterTick命令
      └─ 回滚重放: 重放历史AfterTick命令
```

### 时序保证

与 `TimeSimulator` 的时序完全一致：
```
TimeSimulator:  BeforeTick事件 → World.Tick → AfterTick事件 → AfterTick帧命令
WorldRollback:  Simulate.(BeforeTick) → Tick.(World.Tick) → Tick.(AfterTick)
```

## 五、SnapshotRingBuffer — 环形快照缓存

**文件**: `Rollback/Snapshot/SnapshotRingBuffer.cs`

**内部结构**: `Dictionary<int, TSnapshot>` + `List<int> _frameKeys`（有序）+ `int _capacity`

### 构造函数

```csharp
public SnapshotRingBuffer(int capacity, long maxMemoryBytes = 0, long estimatedSnapshotSizeBytes = 1024)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `capacity` | 必传 | 最大缓存帧数 |
| `maxMemoryBytes` | 0 | 内存预算（字节），0 表示不限制 |
| `estimatedSnapshotSizeBytes` | 1024 | 每个快照粗略估算大小（字节），用于内存预算控制 |

### 核心属性

| 属性 | 说明 |
|------|------|
| `Count` | 当前缓存的快照数量 |
| `MinFrame` | 缓存中最旧的快照帧号（无快照返回 -1） |
| `MaxFrame` | 缓存中最新的快照帧号（无快照返回 -1） |

### Save — 保存快照

```
Save(snapshot)  // snapshot.Frame = 当前帧号
  ├─ 如果该帧已有旧快照 → 调用旧快照.Release() 释放
  ├─ _snapshots[frame] = snapshot 存入
  ├─ _frameKeys 二分查找插入位置，保持有序（O(log n)）
  ├─ removeFrame = frame - _capacity
  │   └─ 如果 _snapshots 中存在 removeFrame → Release + Remove（淘汰）
  └─ 内存预算控制
      └─ 如果 _maxMemoryBytes > 0 且 _currentMemoryBytes 超预算
          └─ 循环淘汰最旧快照（从 _frameKeys[0] 开始）
```

**效果**：缓存中始终保留最近 _capacity 帧的快照，超出范围的自动释放。

### 内存预算控制

- 使用 `_estimatedSnapshotSizeBytes` 粗略估算每个快照的内存占用
- 默认每个快照估算 1KB（1024 字节）
- 当 `_currentMemoryBytes > _maxMemoryBytes` 时，自动淘汰最旧快照
- 淘汰后输出 `Debug.LogWarning` 记录详情
- **注意**：当前使用粗略估算而非精确测量（因精确测量需修改 ECS 模块中的快照实现类，违反模块边界约束）

### TryGetNearestSnapshot — 最近快照查找

```
TryGetNearestSnapshot(targetFrame, out snapshot)
  → _frameKeys.BinarySearch(targetFrame) — O(log n) 二分查找
  → 找到精确匹配 → 直接返回
  → 未找到精确匹配 → 返回 ~index - 1 位置（≤ targetFrame 的最大帧号）
  → 如果没有 ≤ targetFrame 的快照 → 返回 false
```

### ClearBefore — 释放旧快照

```
ClearBefore(frame)
  → BinarySearch(frame) 找到第一个 ≥ frame 的位置
  → 遍历释放该位置之前的所有快照（Release + Remove）
  → _frameKeys.RemoveRange(0, splitIndex)
```

与 `ConfirmFrame` 配合使用，及时释放已确认帧之前的快照内存。

### 快照生命周期

| 操作 | 时机 |
|------|------|
| Capture | World.TryCaptureSnapshot(frame) — 序列化所有 Entity/Component |
| Save | coordinator.SaveSnapshot() — AfterTick 中 |
| Restore | coordinator.RollbackTo() — World.TryRestoreSnapshot(snapshot) |
| Release | 淘汰或 Clear 时 — 释放快照占用的内存 |

## 六、输入管理系统

### 6.1 InputBuffer — 预测输入缓存

**文件**: `Rollback/Input/InputBuffer.cs`

```
内部: Dictionary<int, TInput>
- Save(frame, input): 存入，同帧覆盖
- TryGet(frame, out input): 按帧号取回
- ClearBefore(frame): 清理 frame 之前的缓存（零 GC，使用成员 _recycleKeys 缓冲区）
```

**用途**：回滚重模拟时，按帧号从 Buffer 取回历史输入，逐帧喂给 `world.Simulate`。

### 6.2 AuthoritativeInputBuffer — 权威输入缓存

**文件**: `Rollback/Input/AuthoritativeInputBuffer.cs`

```
内部: Dictionary<int, TInput>
- Save(frame, input): 存入服务端确认的输入
- TryGet(frame, out input): 按帧号查询
- ClearBefore(frame): 清理 frame 之前的缓存（零 GC）
```

**用途**：存储服务端返回的权威输入，用于输入比对和回滚触发判断。

### 6.3 PlayerSnapshotInputApplier — 输入写入 ECS

**文件**: `Rollback/Input/PlayerSnapshotInputApplier.cs`

```
内部:
- _sortedList: List<KeyValuePair<int, Entity>> — 玩家 ID → Entity 映射
- _dirty: bool — 标记排序列表是否需要重建

RegisterPlayer(playerId, entity) → 注册玩家
  → _dirty = true

Apply(world, input)
  → RebuildSortedList() — 按 playerId 排序（确定性保证）
  → 遍历每个玩家
      → world.SetComponent(entity, PlayerInputSnapshotComponent.FromSnapshot(input))
```

**多玩家支持**：`input.playerID` 指定写入哪个玩家的 Entity。

### 6.4 PlayerInputSnapshotComparer — 输入相等比较

**文件**: `Rollback/Input/PlayerInputSnapshotComparer.cs`

```
IsEqual(a, b):
  → moveX / moveY / mouseX / mouseY / mouseWorldX / mouseWorldY → Mathf.Approximately
  → buttonFlags / buttonPressedFlags / buttonReleasedFlags → 逐位 ==
  → 所有字段均等 → true
```

### 6.5 输入时序校验

在 `ReceiveAuthoritativeInput` 中实现两层校验：

1. **过时帧丢弃**：如果权威输入帧号 ≤ `ConfirmedFrame`，说明该帧已确认，直接丢弃并输出警告
2. **重复帧检测**：如果同帧已存在权威输入，比较内容：
   - 内容相同 → 忽略（可能是网络重复包），返回
   - 内容不同 → 输出警告（可能是异常重复包），但仍继续处理

## 七、帧命令回放系统

### FrameCommandSourceAdapter

**文件**: `Rollback/FrameCommand/FrameCommandSourceAdapter.cs`

```
实现 IFrameCommandSource:
  - ApplyCommandsAtTiming(world, frame, timing, isReplay)
      ├─ isReplay=true → applier.ReplayCommandsToWorld(frame, timing)
      │    └─ 重放该帧的历史命令（不消费，不修改命令缓存）
      └─ isReplay=false → applier.ApplyCommandsToWorld(frame, timing)
           └─ 执行该帧的新命令（消费，从缓存移除）
```

**核心问题**：Buff 系统通过 `SimulationFrameCommandBuffer` 注册帧命令（如"第 30 帧施加眩晕"），正常执行会消费命令。回滚重模拟时若再次消费会导致重复施加。

**解决方案**：区分 **Apply**（正常推进，消费命令）和 **Replay**（回滚重放，只读不消费）。

**应用的命令类型**（由 BuffSystem 注册）：
- `AddBuffCommand` — 施加 Buff
- `RemoveBuffCommand` — 移除 Buff
- `BuffEventCommand` — Buff 事件（伤害/治疗/状态变更）
- 其他游戏逻辑帧命令

## 八、Checksum 确定性校验

### 8.1 Checksum 计算管线

```
SaveSnapshot()
  └─ SaveChecksum()
      ├─ uint hash = _world.CalculateChecksum()  — 计算当前World状态Hash
      ├─ _checksumBuffer.Save(new FrameChecksum(frame, hash))
      └─ 后续可与服务端 AuthoritativeChecksum 比对
```

### 8.2 WorldChecksumCalculator — Hash 算法

**文件**: `WorldChecksumCalculator.cs`

```
计算流程:
① GetAllEntities() — 获取所有活着的 Entity
② 按 (ID, Version) 稳定排序
③ 对每个 Entity:
    ├─ Entity Hash: entity.ID * 31 + entity.Version
    └─ 获取该Entity的所有Component类型，按 FullName 排序
        └─ 对每个Component调用 AppendKnownComponentHash()
④ 返回 finalHash (uint)

Hash 累加公式: hash = hash * 31 + value
```

### 8.3 确定性保证

| 措施 | 原因 |
|------|------|
| Entity 按 (ID, Version) 稳定排序 | Dictionary 遍历顺序不确定 |
| Component 类型按 FullName 字符串排序 | GetHashCode 跨平台结果不同 |
| `hash * 31 + value` 自实现累加 | 不依赖 C# GetHashCode |
| float → `(int)(f * 10000 + 0.5)` 量化 | CPU/编译器浮点差异 |
| int → 直接参与乘法累加 | 整型运算确定性保证 |
| 静态缓冲区复用 | 避免每帧分配 GC |

### 8.4 已覆盖的 15 种生产组件

| 类别 | 组件 | Hash 内容 |
|------|------|----------|
| 位置/运动 | PositionComponent | x, y, z |
| | VelocityComponent | x, y, z |
| | MoveSpeedComponent | value |
| 生命/属性 | HealthComponent | current, max |
| | StatComponent | attack, defense, moveSpeed |
| 伤害 | DamageRequestComponent | source, target (ID+Version), amount |
| 输入 | PlayerInputSnapshotComponent | 全部字段（moveX/Y, mouse, 所有button flags） |
| Buff 普通 | BuffRuntimeComponent | 全部字段（target/source, configId, stack, duration/tick/elapsed, priority, buffType） |
| Buff 并行 | CompressedParallelBuffRuntimeComponent | target/source, layerCount, 所有 active layer 的 layerId/expireFrame/elapsedFrames/ticks |
| Buff 请求 | AddBuffRequestComponent | 所有 AddBuffCommand 字段 |
| | RemoveBuffRequestComponent | 所有 RemoveBuffCommand 字段 |
| 空标记 | PlayerTag/DeadTag/ViewDestroyRequest/EntityDestroyRequest | 仅类型名参与Hash |
| 表现 | ViewComponent | viewID |
| | PrefabViewRequestComponent | prefabID |

**未识别组件**：输出 `[Checksum] Unhashed component` 警告，防止静默漂移。

### 8.5 IDeterministicHash — 组件自描述接口

**文件**: `IDeterministicHash.cs`

```csharp
public interface IDeterministicHash
{
    void AppendHash(ref uint hash);
}
```

组件实现此接口后，`WorldChecksumCalculator` 优先通过反射检测并直接调用，无需手动注册到 `AppendKnownComponentHash`。

**处理优先级**：
1. 检查组件是否实现 `IDeterministicHash` → 调用 `AppendHash()`
2. 回退到 `AppendKnownComponentHash()` 硬编码匹配
3. 均未命中 → 输出 `[Checksum] Unhashed component` 警告

## 九、确认帧机制

**涉及文件**: `RollbackCoordinator.ConfirmFrame()`、`RollbackBootstrap.ConfirmFrame()`

### 设计目的

联机对战中，服务端定期广播已确认的逻辑帧号。客户端收到后释放该帧之前的所有缓存数据，确保内存不无限增长。

### 调用链路

```
网络层收到服务端确认消息
  → RollbackBootstrap.ConfirmFrame(30)
    → RollbackCoordinator.ConfirmFrame(30)
      ├─ 检查 frame > _confirmedFrame（防止退化确认）
      ├─ _confirmedFrame = 30
      ├─ _inputBuffer.ClearBefore(30)                 // 释放帧1~29 预测输入
      ├─ _authoritativeInputBuffer.ClearBefore(30)    // 释放帧1~29 权威输入
      ├─ _checksumBuffer.ClearBefore(30)              // 释放帧1~29 本地Checksum
      ├─ _authoritativeChecksumBuffer.ClearBefore(30) // 释放帧1~29 权威Checksum
      └─ _snapshotBuffer.ClearBefore(30)              // 释放帧1~29 快照
```

### 安全性保证

- **防止退化**：`frame <= _confirmedFrame` 时直接忽略，输出警告
- **批量释放**：一次性清理所有 Buffer 的历史数据
- **与回滚协调**：`ReceiveAuthoritativeInput` 中会检查过时帧（`frame <= _confirmedFrame`），直接丢弃

### 对回滚的影响

确认帧机制意味着：
- 回滚只能回滚到 `_confirmedFrame` 之后的帧（已确认帧的快照被释放）
- 这意味着服务端需要保证：在确认某帧之前，该帧的权威输入已经发送并处理完毕

## 十、加速追帧机制

**涉及文件**: `RollbackCoordinator.TickMultiple()`、`RollbackBootstrap.Update()`、`RollbackBootstrap.SetExpectedFrame()`

### 设计目的

客户端因卡顿、断线重连等原因落后服务端多帧时，在单个 Unity 帧内加速执行多个逻辑 Tick，快速追上进度。

### 调用链路

```
每 Unity 帧 Update()
  → framesBehind = _expectedFrame - CurrentFrame
  → 如果 framesBehind > 1:
      → ticksToRun = min(framesBehind - 1, MaxTicksPerUnityFrame)
      → coordinator.TickMultiple(ticksToRun, inputProvider)
        → for each tick:
            → coordinator.Step(input)
```

### 参数控制

| 参数 | 来源 | 默认值 | 说明 |
|------|------|--------|------|
| `_expectedFrame` | `SetExpectedFrame(n)` | 0 | 服务端期望客户端到达的帧号 |
| `MaxTicksPerUnityFrame` | `coordinator.MaxTicksPerUnityFrame` | 3 | 每 Unity 帧最多执行逻辑 Tick 数 |

### 安全性保证

- **上限保护**：`Math.Min(count, MaxTicksPerUnityFrame)` 防止单帧追帧过多导致卡顿
- **保留裕度**：`ticksToRun = framesBehind - 1`，留 1 帧由正常的 OnBeforeTick 驱动
- **输入连续**：每帧通过 `inputProvider` 获取对应帧的输入，确保追帧过程输入数据完整
- **可动态调整**：`MaxTicksPerUnityFrame` 可根据网络延迟动态设置

## 十一、Checksum 漂移检测

**涉及文件**: `RollbackCoordinator.VerifyChecksum()`、`RollbackCoordinator.OnChecksumDrift`

### 设计目的

检测客户端与服务端模拟结果的不一致，及时发现状态漂移问题。

### VerifyChecksum 逻辑

```csharp
public ChecksumComparisonResult VerifyChecksum(int frame)
{
    // ① 取出本地 Checksum
    if (!_checksumBuffer.TryGet(frame, out var local)) return fail;

    // ② 取出服务端 Checksum
    if (!_authoritativeChecksumBuffer.TryGet(frame, out var auth)) return fail;

    // ③ 比对
    bool match = local.Value == auth.Value;

    // ④ 不匹配时触发事件和日志
    if (!match)
    {
        Debug.LogWarning($"[RollbackCoordinator] Checksum drift detected ...");
        OnChecksumDrift?.Invoke(frame, local.Value, auth.Value);
    }

    return new ChecksumComparisonResult(match, frame, local.Value, auth.Value);
}
```

### 事件回调

```csharp
// 签名: Action<int frame, uint localChecksum, uint authoritativeChecksum>
public event Action<int, uint, uint> OnChecksumDrift;
```

外部可订阅该事件实现自定义处理（如：上报服务器、弹出错误提示、记录日志文件等）。

### ChecksumComparisonResult 结构

| 字段 | 说明 |
|------|------|
| `IsMatch` | 本地与服务端 Checksum 是否一致 |
| `Frame` | 比对的目标帧号 |
| `LocalChecksum` | 客户端本地计算的 Hash 值 |
| `AuthoritativeChecksum` | 服务端返回的 Hash 值 |

### 典型使用场景

- **开发调试**：每次快照保存后比对，快速发现非确定性逻辑
- **联机对局**：定时比对关键帧，检测异常状态漂移
- **赛后回放**：全量比对，验证回放结果一致性

## 十三、回滚触发时数据流

```
网络层调用: RollbackBootstrap.ReceiveRemoteInput(30, authoritativeInput)
  │
  ├─ coordinator.ReceiveAuthoritativeInput(30, authoritativeInput)
  │   │
  │   ├─ ① 时序校验: frame=30 <= confirmedFrame? → 过时则丢弃
  │   ├─ ② 重复检测: 同帧已存在相同权威输入? → 忽略
  │   │
  │   ├─ _authoritativeInputBuffer.Save(30, input)
  │   │
  │   ├─ _inputBuffer.TryGet(30, out predictedInput)
  │   │   └─ 无预测输入 → 直接返回
  │   │
  │   ├─ _inputComparer.IsEqual(predictedInput, authoritativeInput)
  │   │   └─ 一致 → 直接返回（无回滚）
  │   │
  │   ├─ 不一致 ↓
  │   │
  │   ├─ preRollbackFrame = CurrentFrame（记录回滚前帧号）
  │   │
  │   ├─ RollbackTo(29)
  │   │   ├─ TryGetNearestSnapshot(29, out snapshot) — O(log n) 二分查找
  │   │   │   └─ 遍历所有快照 → 找帧号 ≤ 29 且最大的 → 帧 25
  │   │   └─ _world.Restore(snapshot)
  │   │       ├─ 清空当前 World 的 Entity / Component / ArcheType / Singleton
  │   │       ├─ 按快照重建所有 Entity
  │   │       ├─ 恢复所有 Component 数据
  │   │       └─ 恢复 ArcheType 分配表
  │   │       CurrentFrame = 25
  │   │
  │   ├─ _inputBuffer.Save(30, authoritativeInput) ← 覆盖帧30输入
  │   │
  │   └─ ResimulateTo(45)
  │       while CurrentFrame < 45:
  │         帧 26:
  │           _inputBuffer.TryGet(26) → 预测输入（moveX=+1）
  │           _world.Simulate(input, ctx)   ← ctx.isRollback=true
  │           _world.Tick(ctx)
  │           _world.Capture(26) → 保存新快照
  │           SaveChecksum()
  │           CurrentFrame = 26
  │         帧 27: ... (同上)
  │         ...
  │         帧 30:
  │           _inputBuffer.TryGet(30) → 权威输入（moveX=-1）← 覆盖后的值
  │           ... Simulate + Tick + Capture ...     ← 路径从此不同
  │         ...
  │         帧 45: ... CurrentFrame = 45
  │
  └─ Runner.SetFrameCount(45) ← 对齐 Runner 内部帧号
```

## 十七、性能优化设计

### 17.1 零 GC 设计

| 优化项 | 涉及文件 | 实现方式 |
|--------|---------|---------|
| ClearBefore 零 GC | `InputBuffer`、`AuthoritativeInputBuffer`、`ChecksumBuffer`、`AuthoritativeChecksumBuffer` | 使用成员 `_recycleKeys: List<int>` 缓冲区替代临时分配 |
| 二分查找 | `SnapshotRingBuffer` | `_frameKeys` 维护有序列表，`BinarySearch` O(log n) 替代 O(n) 线性扫描 |
| 静态缓冲区复用 | `WorldChecksumCalculator` | 静态 `_entityBuffer` 和 `_typeBuffer`，避免每次 Calculate 分配 List |

### 17.2 内存预算控制

| 控制维度 | 实现 | 说明 |
|---------|------|------|
| 帧数限制 | `SnapshotRingBuffer._capacity` | 默认 120 帧，超出自动淘汰 |
| 内存限制 | `SnapshotRingBuffer._maxMemoryBytes` | 0 表示不限制，>0 时超预算自动淘汰最旧快照 |
| 估算方式 | `_estimatedSnapshotSizeBytes` | 默认 1024 字节/快照（粗略估算，可通过构造函数调优） |
| ConfirmFrame 释放 | `Coordinator.ConfirmFrame()` | 服务端确认后批量清理所有缓存 |

### 17.3 查找性能

| 操作 | 实现 | 复杂度 |
|------|------|--------|
| `TryGetNearestSnapshot` | 二分查找有序 `_frameKeys` | O(log n) |
| `Save` 插入/替换 | Dictionary + 二分查找 Insert | O(log n) |
| `ClearBefore` | 二分查找分割点 + RemoveRange | O(n) |

## 十八、关键设计约束

| 约束 | 原因 |
|------|------|
| Simulate 只写输入和 BeforeTick 命令，不 Tick | 与 TimeSimulator.OnBeforeTick 语义对齐 |
| Tick 执行 World.Tick 后执行 AfterTick 命令 | 与 TimeSimulator.OnAfterTick 时序对齐 |
| 快照仅 World.Idle 时保存 | AfterTick 后 World 回到 Idle，此时安全 |
| 回滚到 frame-1 的最近快照 | 回滚到错误帧执行前的状态 |
| Simulate + Tick + Capture 在 ResimulateTo 内连续执行 | 保证单次回滚中 World 状态一致 |
| FrameCommand 按 BeforeTick / AfterTick 分阶段 | 正常推进和回滚重放时序一致 |
| 所有输入写入不绕过回滚管线 | 保证预测输入被正确缓存，供回滚重放 |
| 修改仅限回滚系统目录内 | 保持模块边界清晰，不入侵 ECS/View/BuffSystem |
| ConfirmFrame 只增不减 | `frame <= _confirmedFrame` 直接忽略，防止退化 |
| TickMultiple 受 MaxTicksPerUnityFrame 限制 | 防止单帧追帧过多导致 Unity 主线程卡顿 |
